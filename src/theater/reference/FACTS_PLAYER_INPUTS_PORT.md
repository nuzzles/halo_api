# Cached player assembly integration

`facts_player_inputs.rs` bridges decoded cache facts to the existing player
assembly. `replay_from_film.rs` now has one internal pure assembly boundary used
by both paths. Neither the bridge nor that boundary constructs a synthetic Film,
reads chunks, or manufactures packet/bit source references. This is reference-port
integration, not the deferred Film/ResolvedFilm architecture.

The bridge preserves cached positions' world-presence flag, timestamps, slot,
world float values, yaw/pitch presence, health/shield presence, biped creation
identity, native fire index, deaths, player-index table, bootstrap seats, player
teams and clock origin. Rich cache fields unused by player publication remain in
NativeFilmFacts. Statborg records and bots remain explicit caller inputs; file
sections are not implicitly installed as though native BuildFromFacts did that.
Cached zoom events feed the shared scope reduction directly, retaining native
signed levels. Scope periods now use i64: positive levels above 255 remain exact,
while zero and negative levels close periods. The existing recording API maps its
byte-sized wire levels into the same pure reduction.

The exact cache and the older replay DTO domains are different. The checked
adapter reports FactsProjectionError for non-UTF-8 strings; it does not silently replace strings or narrow values.
Those are explicit remaining domain limitations, not native-compatible rejection
claims. Cache bytes and exact DTOs remain intact. Nil collection distinctions are
kept by the cache; empty collections are projected only where player consumers
already operate on collections without a nil distinction. Transient source-scan
collision diagnostics are not present in the native cache; the returned legacy
ReplayIdentityEvidence cannot reconstruct them and uses zero/no scan error.

The independent pinned oracle runs native BuildFromFacts on 128 encoded/decoded
files. Rust comparisons cover frame grid, duration/origin, bounds, tracks (including
scope and vitality), roster and identity publication. A separate 1,024-case native
scope oracle exercises signed extrema and positive levels through i64::MAX, native
input order, life/hold boundaries and queries on both sides of closure times.
The fixtures are native outputs, not expectations generated by Rust. Validation
results are recorded in facts-player-inputs-validation.json. Host player/scope
tests, 86 replay regressions, Clippy and actual WASM runtime pass. The six-film
recording-path comparison passed in debug profile in 2774.30 seconds. It validates
the player-boundary snapshot compiled before subsequent cache adapter changes;
it is not validation of those later adapters. Future full-film runs should use
release profile.

Remaining: full document input conversion, pre-assembly capture, fallback counter
restoration, caller-option precedence and all representable native replay domains.
Do not mark BuildFromFacts or all-data v41 parity complete from this player subset.

Player-index readings and disagreements now retain signed i64 through the cache
bridge, effective table, owner output, bridge health and identity-link readings.
The native source scanner increments these counters with wrapping arithmetic.
The expanded signed-layer oracle supplies all 121 pairs of eleven values spanning
negative, above-u32 and signed extrema to native BuildFromFacts and compares whole
typed documents and ordered logs. This closes the player-index counter boundary;
bootstrap-seat/team-scan counters have since been migrated as described below.
See signed-layer-validation.json for the current validation scope.

Bootstrap occupied/vacant and all eleven team-scan counters now retain i64 through
the cache bridge. Occupied seats remain signed in identity-table coverage; team
records, rejected totals and divergence totals remain signed in published team
coverage. Rejection/divergence sums and source scanner increments wrap as native
integers do. Native `Read > 0` remains the independent team-read gate.

The shared signed-layer fixture includes signed seat counts and all eleven selected
values in each team counter. Full-document checks exercise consumed values and
ordered logs; the input combinations are synthetic and not exhaustive. Other legacy DTO counters remain to audit. Caller Options.MinPoints now retains
signed i64 through the track threshold and published coverage on both platforms.
Raw player names and null distinctions remain open. Build/refusal/component
metadata now preserves bytes, as described below.

Bootstrap build/refusal and team component metadata now use ReplayByteString.
The cache bridge preserves all bytes, and identity-table refusal coverage retains
those same bytes. Empty checks and source component matching inspect raw bytes.
JSON and runtime log strings apply native UTF-8 replacement only at the output
boundary; this conversion does not alter the retained raw metadata.

The signed-layer oracle now injects eight metadata strings into each field,
including malformed UTF-8, an incomplete sequence, embedded NUL/newline and valid
non-ASCII text. Tests compare raw projected bytes, the complete team-report JSON,
raw composed refusal coverage, whole typed documents and ordered native logs.
These are cache-domain checks; they do not prove arbitrary raw source registry or
player-name fidelity. Death and bootstrap-seat gamertags still report explicit
FactsProjectionError until the downstream identity/name graph is migrated.

## Human name byte preservation

Death and bootstrap-seat gamertags now use ReplayByteString. Raw names survive
identity table maps, identity_player_names, published identity/roster/track name
fields and gamertag-to-XUID lookup. The cached player projection no longer rejects
its raw names; its existing Result/error type remains an API compatibility shell.
Caller bot identity fields and other legacy string domains remain separate work.

Name lookup accepts bytes and retains exact bytewise keys. Decimal `xuid:` parsing
is checked for overflow and never falls back to a same-named gamertag on malformed
input. Seat-presence and usage grouping preserve bytewise roster bot keys instead
of formatting names through a lossy display conversion.

The complete document oracle compares raw roster and identity names against
hex-encoded native output as well as typed JSON/logs. A separate native application
adapter oracle has 169 death-name pairs and 2,197 lookup queries, including two
distinct invalid single bytes that JSON renders identically, first-name precedence
with XUID zero and malformed/overflowing xuid prefixes. This is synthetic native
agreement, not independently annotated film evidence or complete bot-name fidelity.

## Bot name byte preservation

IdentityBot.name, IdentitySuccession.bot_name, ReplayTrackIdentity.bot and
ReplayTrack.bot now retain raw bytes. Bot-seat ambiguity and roster deduplication
compare exact names. Presence and usage grouping concatenate the raw bot prefix
without display conversion. Existing valid source metadata converts losslessly.

The native raw-bot oracle checks all 81 pairs of nine chosen names. It includes
56 shared-seat refusals, 54 named replacement-chain cases and 27 cases without
clock evidence. Rust compares raw seat names, direct track names, roster entries,
presence keys/envelopes and replacement results. Focused native output agreement
does not establish every bot runtime diagnostic or full-film bot reconstruction.

ReplayTrack.points now preserves native nil/null separately from an explicit empty
array. Point-consuming reducers borrow an empty slice for nil without modifying
its representation. Native source publication still produces explicit point arrays.
The dedicated nullable-track oracle and unnormalized bomb-carry fixture validate
this boundary; other nil/empty distinctions remain part of the final audit.
