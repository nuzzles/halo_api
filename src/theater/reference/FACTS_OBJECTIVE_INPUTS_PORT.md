# Cached free-object lives and flag carry inputs

free_facts_objective_lives and build_facts_replay_objective_objects share the
recording reducers through consumed-field values. Full u32 keys and u64 timestamps
survive grouping and native sorting. Identity uses presence-gated low-u32 MPP data;
last declared identity wins per key before sorting. Track selection reuses native
lifetime matching and tie precedence, with no evidence from nil/empty point lists.
The selected track contributes only monotonically later timestamps after creation,
as the reference does; position projections do not fabricate source coordinates.

Raw free-object lives retain both flags and balls. Published objective objects use
the reference's ball-only family gate, nonempty label gate, scanned/step gates,
frame-window rejection, and last-reading-per-frame replacement. Caller labels and
families still use the existing String domain; broader raw-string reconciliation
remains required for complete parity.

The already-pinned facts-ground-objects fixture now validates its previously
unasserted objective fields: 1,024 raw free-life comparisons and 5,120 full
objective-publication comparisons. These reuse native expectations generated by
halo_rust_facts_ground_objects_test.go.txt, not Rust-generated expectations.

mark_facts_replay_flag_carries consumes marks and keyframe times directly from
FactsCarrierMarkScan; native markFlagCarries does not consume Records/BipedRecords.
The signed cache counters are neither narrowed nor copied into a fabricated source
scan. ReplayFlagScan has a default marker type preserving the recording API;
FactsReplayFlagScan and build_facts_replay_flags reuse the full carry reducer with
cached marker evidence. Observability and confirmation remain distinct, and native
carry closure, free-object assignment, coverage and fallback accounting are shared.

The pinned replay-flag-geometry fixture now also checks the cache adapter: 1,024
marker confirmations and 2,048 carry publications (free lives supplied/empty).
The test compares carries, coverage and both returned fallback counts against the
native fields. It does not imply complete cached document/statborg integration.

## Integration still required

FilmInputs.applyTo overrides Flag.Marks, Flag.Gauge and Flag.GaugeScanned while
preserving caller flag options. Zone.Reads and Zone.Scanned come from the cache;
zone catalogs, roles, teams and hill configuration remain caller inputs. Bomb.Reads
comes from the cache while recognition and other bomb options remain external.
ManagedPropertyRead and NavpointRadialRead are already shared native/cache types;
the eventual composer should pass them directly and preserve explicit scanned
booleans instead of recomputing them from available geometry or nonempty slices.

Cached statborg named-event passes, identity and published player evidence still
need complete document composition. Native flag assembly makes two named-event
passes even when its scanned flag is false; retain their observation order.
Flag return gauges attach after carry assembly. Zone and bomb composition must
retain mode gates, clock offsets, caller configuration and observation boundaries.
No Film/ResolvedFilm/playback architecture work is started here.

See facts-objective-inputs-validation.json for actual validation scope.

## Cached flag layer assembly

`build_facts_replay_flag_layer` runs both named-event passes in native order even
when Scanned is false. It uses the caller identity when Resolved is true, including
resolved empty maps, otherwise resolves identity from death instants only after
recognizing CTF. It consumes FactsDeath without decoding unused gamertag bytes.
The source and cached paths share carry bounding through identity/time values.

The layer receives free-object evidence from the cached weapon scan and assigns
ObjectLives only in the recognized branch. It attaches return gauges after carry
assembly and preserves GaugeScanned independently of nonempty readings. No Film
or source read is manufactured. The context retains exact cached deaths while
source ReplayFlagContext keeps its default IdentityDeath type.

The new native facts-flag-layer fixture calls attachFlagCarries and captures
published carries, coverage, fallback counters and ordered objectives diagnostics.
Its 128 cases exercise unresolved/named/resolved-empty identity, scan gates,
chronology warnings and gauges. Existing free-object, geometry and gauge fixtures
remain complementary evidence; this new fixture supplies empty free lives and
marker scans. FlagReturnZone and full document/runtime log attachment remain to
be wired by the composer.

## Cached VIP and skull assembly

`build_facts_replay_vip_crown` respects the mode gate before named-event observation
or identity resolution. VIP always resolves its own identity from supplied records
and death instants; it has no caller identity override in the native options.
Its period reducer shares source calculations using death identity/time values;
unused cached gamertag bytes never enter text conversion.

`build_facts_replay_skull_carries` takes explicit mode, record, identity and cached
death inputs. Like flags, skull carries preserve a resolved caller identity even
when it names nobody, falling back only for an unresolved identity. It reuses the
existing skull reducer and caller-provided published-track presence.

The native VIP diagnostic fixture supplies 128 assembly cases including disabled
mode gates and chronological diagnostics. A new 128-case skull assembly fixture
calls native attachSkullCarries with unresolved, named and resolved-empty identity,
plus deduced-track presence. It expects 61, 24 and zero published carries for those
identity modes. These are synthetic native comparisons; positive captured v41 VIP
and Assault evidence is still absent. Full composer runtime logs remain open.
