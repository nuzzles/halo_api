# Native pickup padding and scanner counters

Reference: JGtm/LevelUp `feat/v75`, commit
`43a01721e8a02c87c955e175936f0ccf8dd97a81`.

`pickup-padding-v41.json.zlib` is zlib-compressed JSON generated by
`reference/halo_rust_pickup_padding_test.go.txt` in the native grammar package.
The general `reference/generate_oracles.py` runner registers this harness.

The production `decodeBipedPickup` supplies acceptance, slot, class, catalog,
and all counters for 3,328 direct inputs. A separate native reader walk measures
the logical endpoint. This includes 204 accepted inputs, 131 extending beyond
physical source bytes, empty lists, alternate types, config-clear inputs, absent
first references, wide references, absent catalogs and continuation bits.

Three actual `ScanBipedPickups` calls cover a source with no biped band, a source
whose keyframe discovers slots 520 through 523, and an empty contiguous-prefix
control. Each nonempty source examines 1,752 candidate packets. The first
publishes 140 pickups; the second refuses all 140 off-band. The harness checks
its instrumented source walk and counters against the production scanner before
writing results. Packet ordinals, ranges and nonmonotonic wire timestamps are
retained; pickup scanning preserves source order and does not sort by time.

Rust retains every native attempt and its refusal outcome, raw references,
logical end, physical source length and padded extent. Catalog and actor
recordedness are explicit. Bounded gameplay pickups remain separate. Synthetic
catalog zeros are native reader behavior, not evidence of a recorded catalog.
Constructor tests exercise all three Film constructors and complete JSON export.
This synthetic differential suite is not an independent gameplay annotation.
