# Automatic Film weapon-hit retention

Reference commit: 43a01721e8a02c87c955e175936f0ccf8dd97a81.
Native oracle: weapon-hit-corpus-v41.json.zlib, generated by
../reference/halo_rust_weapon_hit_corpus_test.go.txt using native shot/damage
scanners and PairWeaponHits, with and without the native distance resolver.
No expected values are generated by the Rust Film constructor.

The constructor regression `local_weapon_hit_film_retention` uses all six captured
films and checks automatically retained shots, damage observations, biped landing
base and no-distance aggregate statistics against the native fixture. It checks
shot and damage packet provenance against the loaded source and roundtrips the
complete Film export. The fixtures contain 4,395 shots and 105 damage observations,
including empty-film controls. This test does not invoke retain_weapon_hits.

The existing map-constructor regression now checks automatically retained output
against the direct scan with the resolved sampling map. Its direct-scan comparison
is an integration check, not independent native evidence. The existing native
six-film aggregate and track comparisons separately test distance computation;
a separate map-constructor test now checks that previously unverified integration.

The existing non-map regression checks a positive shot/hit without distance,
missing native chunk-one prefix refusal with the rest of Film retained, failed explicit
refresh preserving the previous result and recording an error, successful retry
clearing the error, and old exports lacking both fields. Native raw damage-reader
comparisons separately cover all additional raw scalars and padded endpoints.

Automatic map loading performs a second weapon-hit scan after sampling precision
resolves, adding track and distance evidence. This increases constructor work and
export size. Missing distance evidence remains separate from failed direct reads;
computed hit pairing and distance buckets are interpretations, not wire fields.
The three-layer architecture remains deferred.

## Map-constructor comparison

`local_weapon_hit_film_map_retention` constructs all six films with explicit
native catalog bounds and the established 13-bit frame ID layout. It first checks
that the resolved sampling map equals the reference input. It compares all shots,
damages, landing bases, complete distance histograms, distance bases, error status,
and all 590,758 native track samples, including each sample timestamp and position.
It checks shot/damage source references and roundtrips the retained FilmWeaponHits
export. The whole Film roundtrip remains covered by the base corpus and synthetic
map-constructor tests; this captured map test serializes the hit result only.

Both constructor corpus tests use the same bootstrap/gameplay-chunk prefix as the
native weapon-hit fixture; footer content is outside that scanner's input range.
This is not a new full-document comparison or independent observation of physical
hits. Native hit pairing and distance inference remain labeled derived data.
