Additional reference commit: `d61443ef59268ad734355db8e9974f68db5ca6d0`.
The prior reference remains pinned separately at `43a01721e8a02c87c955e175936f0ccf8dd97a81`.
Source: `internal/grammar/composants_vue_b_m4b.go`, its dispatch chain and existing
leaf readers. The independently executed Go generator is
`reference/halo_rust_m4b_components_test.go.txt`.

The fixture contains 3,584 actual Go dispatch reads: 512 for each of six newly
supported names and 512 for an unknown-name negative control. Inputs cover all
eight bit alignments, zero/one-filled bytes and deterministic random bits. Each
row retains input bytes, start/end positions, ported status and the next eight
bits. The reader uses the reference instrument context, level 1, archetype 0.
Inputs are 128 bytes; these cases do not establish truncated-input equivalence.

The Rust comparison checks dispatch status, exact endpoint, the following byte,
continuous coverage of consumed source bits, raw field equality and JSON round
trips. Runtime assumption counters are independently checked for merge behavior
and absent-field compatibility in older exports. This fixture was generated by
Go before applying the Rust port; Rust output did not generate expectations.

The new fields are personal-AI handle/optional quantum, aim-assist reference/flag,
player frame configuration, looping-sound word, vehicle EMP timer quantum and
vehicle-type-physics orientation/angular-velocity values. Quantized values remain
raw; no player association or gameplay interpretation is introduced.

Vehicle type physics has a runtime gate at object byte +0x818 which is not read
from this component. The reference assumes it is set when decoding the component.
Rust follows that policy and increments `vehicle_type_physics_assumed` in parser
diagnostics before reading, including on refusal. This is not a recorded bit.
The corpus-level validity of the assumption remains subject to upstream evidence;
synthetic endpoint agreement alone does not establish its universality.

The shared dispatch reaches native frame/keyframe readers. Older fixtures still
expect these components to be unsupported; their stopping points require explicit
migration against the updated independent reference. No whole-film completeness
or unchanged full-corpus counts are claimed by this leaf-reader comparison.
