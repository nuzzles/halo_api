# Captured native scan inputs before replay publication

Pinned reference: LevelUp `43a01721e8a02c87c955e175936f0ccf8dd97a81`.
Harness: `../reference/halo_rust_full_document_test.go.txt`,
`TestHaloRustFullDocument`. Inputs are the actual `scanFilmInputs` result from
six captured v41 films, before document publication filters or decimation.
No expectations are generated by Rust. Every previously retained document field
was verified unchanged when the reference fixture was expanded.

All 44 exported native FilmInputs fields are retained in six separately compressed
`full-document-inputs-N-v41.json.zlib` files. Each row of the existing document
fixture identifies its input file. The generator's write_full_document_oracles
helper writes these files and the document references together. The full raw
oracle is about 445 MB; retaining it separately avoids embedding it in the test
binary or parsing all six films into serde_json::Value at once. Selected inputs are
materialized one film at a time.

The native struct cannot be JSON-encoded directly because calibration maps have
structured MPP-width keys. The harness preserves those maps as key/value entry
arrays sorted by the JSON encoding of each key. Other JSON-compatible native
values retain their ordinary representation. This is an explicit reference
projection of public fields, not an assertion that native FilmInputs has a JSON
wire schema. Unexported native implementation state is not included.

The previous checkpoint verified 20 fields; the current comparison extends this
to 29 fields. The original fields are: FilmMajorVersion, Fire, Loadouts,
BipedCreations, PlayerTeams, TeamScan, FilmTable, WeaponChanges, MovementStates,
MovementStateStats, Grenades, AbilityChargeStats, AbilityCharges,
AbilityImpulseStats, AbilityImpulses, GrappleReads, CamoStates, AbilityRanks,
PickupStats and Pickups. The added fields are Inventory, InventoryDeltas,
InventoryDeltaAmmoRefused, EquipmentChanges, EquipmentChangeStats, SpawnEvents,
SpawnStats, FilmClockOriginUS and ZoomEvents. Every record and field in these collections is compared
in order, including source packet indices and timestamps where present. Nil
collections are normalized only against empty Rust collections. Fire Aim values
are normalized through their declared float32 type; inventory Gauge values are
normalized through their declared float64 type, including JSON's integer spelling
of zero. No numeric tolerance is used. The initial expanded run found only three
0-versus-0.0 gauge representations in Bandit, not a disagreement in gauge values.

The test streams past the other fields with IgnoredAny, while retaining all of
them in the fixtures for further checks. It checks the 44-field source shape and
all 29 selected fields are present. The explicit remaining list and source hashes
are in ../reference/film-input-retention-coverage.json. A final-document match
does not count as proof of those remaining intermediate outputs. These captured
reference comparisons also do not replace independent semantic action goldens or
prove complete parser parity.

The expanded 29-input and complete-document comparison passed all six films in
82.17s. All input fixture hashes remain unchanged. Fifteen fields still require
this integrated comparison. FilmClockOriginUS is now read from the retained
native source result on Film, with explicit read/failure/unavailable distinctions.
